# Engineering notes — not a transcript

These notes describe the actual development work. They are distinct from the verbatim visible conversation in `session.md`. No model output or benchmark result is invented here.

1. Read the full live brief/FAQ and both supplied ZIP archives. The web retrieval tool could not open the brief, but an ordinary HTTP fetch succeeded. Read the checker/schema and tiny worked example. No challenge chats were sent to a third-party service during development.
2. Verified that no `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, OpenRouter key or OpenAI key was configured. This constrained verification to local logic and a simulated model endpoint. A real model benchmark remains outstanding.
3. Measured the original naive starter with the unchanged official checker: approximately 5.4/56 on dev. The page's stated baseline is a different, model-using baseline: 17.5/56.
4. Inspected aggregate label structure and representative messages locally. The dev set has 4,502 messages, 138 chats and 286 participant IDs other than ME; 51 circles are labelled and ten of those are seeded. All 49 done labels omit closing evidence. Seventy-four loop records use 63 distinct source sets, with some repeated/conflicting statuses. These observations influenced conservative closure and honest error reporting, not dataset-specific person/task mappings.
5. Implemented a standard-library pipeline: stable-ID corpus indexes; rule priors; organisation pass; person dossier batches; chronological extraction; later-evidence retrieval/review; goal selection; normalization/policy. Kept every organisation/person name from the dev data out of executable inference code. No runtime component reads `answers/`.
6. Added private response caching, usage accounting, bounded provider retries, JSON-format compatibility, four-way concurrency, a deadline and request-count cap. Invalid provider/authentication responses fail visibly rather than quietly falling back to the zero-cost mode. Off-endpoint redirects are rejected.
7. First rules checkpoint scored approximately 21.4/56 with 431 predicted loops. Error inspection showed newsletter/rhetorical question false positives and a deduplication problem: excluding numbers could merge distinct payments. Added a general article filter, better source checks, numeric tokens, and a shorter repetition window. The resulting measured checkpoint is 21.91/56 with 341 loops, 46 source matches, 23 correct matched statuses and one false closure of a labelled-open loop. These remain weaknesses, not solved problems.
8. Fixed an unsafe JSON recovery approach that could accept a complete nested object from an otherwise truncated response. The parser now accepts only a complete first object. Added a regression test. Also hardened normalization against invalid field types and preserved reasonable reminder times anchored to the data snapshot.
9. Wrote tests on invented conversations for source/chat integrity, chronology, false acknowledgements, permissions, private preparation, seed/correction precedence, relative dates, goals, voice text, order invariance, renamed IDs and malformed fields. A local HTTP server exercises the real OpenAI-compatible request path through the entire model pipeline and proves cache replay/accounting. Those responses are test fixtures, not a semantic model benchmark.
10. The 24-test suite also passes on a synthetic 20,000-message / 320-chat input in offline mode. This checks input scale and assembly; it does not establish a live model's hidden-set runtime. The supplied `check.py`, `schema.json` and `run.sh` bytes were verified against the starter archive.
11. Prepared a short write-up, exact aggregate report, user guide and interview notes. The guide explicitly requires a live model benchmark before asserting model quality/cost, and distinguishes a tested zero-cost submission from a model-assisted submission. The user must use their own registration identity and commit SHA when submitting.
12. Final packaging uses a source allowlist, excludes real chats/predictions/caches/keys, and preserves the executable bit on `run.sh`. A fresh extraction is used to check one-command operation and the tests. No GitHub publication or assessment-form submission has been performed in this session.
